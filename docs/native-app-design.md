# 瑞幸 iPhone App 实机设计调研

2026-10-15 使用真实 iPhone 上的瑞幸咖啡 App 逐页观察。以下是当日界面行为与设计记录，不将 App 内的功能视为 AI 开放平台 MCP 已提供的接口。包含账号、门店和历史订单的原始截图仅保存在本机忽略目录 `research-private/2026-10-15/`。

## 场景与路径

| 场景 | 观察到的路径与行为 | 插件关联 |
| --- | --- | --- |
| 发现与选店 | 首页进入菜单；菜单顶部先选择自提或外送，再选门店。门店选择页结合地图、附近列表、营业信息与搜索；外送另有地址选择。 | `queryShopList` 能支撑门店搜索；宿主内的门店区域需要明确展示配送方式与选店状态。 |
| 菜单浏览 | 经典菜单采用横向专题加左侧品类目录，商品卡片有实物图、短标签、描述、预估到手价、原价和快速加购；另有每周特价专题与“我的常点”。 | 当前开放接口只支持关键词搜索，不能据此虚构完整菜单、专题或历史偏好。可借鉴搜索结果卡片的视觉层级。 |
| 搜索与商品 | 搜索页提供历史与推荐词；结果在当前门店范围内展示。商品详情有大幅图片、规格选择、预估价格、数量、加入购物车、立即购买，以及下方长图、原料与价格说明。 | 现有 `searchProductForMcp`、`queryProductDetailInfo`、`switchProduct` 对应可用的核心环节。规格更新应以官方返回的新 SKU 和价格为准。 |
| 购物车与结算 | 购物车以底部抽屉呈现商品、规格、数量与预计优惠；结算页依次显示门店与预计时间、商品、加购推荐、优惠组合、实付金额、支付方式、备注和发票入口。优惠券按适用性及到期状态分组。 | 插件应优先呈现选中商品、规格、门店及真实预览金额，金额旁标注“预估”或“订单预览”；不要把 App 内的会员、优惠券和支付能力假定为开放接口的一部分。 |
| 支付边界 | 同一结算页选择不同付款方式时，底部按钮文案不同：实机观察到“免密支付”和“提交订单”。 | 插件仍执行订单预览与显式确认；支付留给瑞幸官方渠道。不能以按钮文案推断所有支付方式、地区和账号的后续流程一致。 |
| 订单与权益 | 历史订单按门店、卡券、即享等类型分组；详情页有取餐信息、商品、优惠、备注及重购入口。个人页集中展示券、会员权益、礼品卡和服务入口。 | 现有官方 MCP 仅支持按订单号查单，不应在插件内伪造完整订单历史。 |
| 其他业务 | “瑞幸即享”是独立的实物商品商城，有商品目录、规格、运费、赠品和独立购物车。礼品卡可选卡面、祝福语及现金或咖啡券类型；现金卡页可配置面额和数量，底部提供支付入口。拼单入口提示跳转微信小程序。AI Lucky 提供语音入口和预设场景，页面要求先阅读授权提示。 | 这些功能均不属于当前社区插件的已确认开放能力，先作为体验边界记录。 |

## 视觉规律

- **品牌层级**：以瑞幸蓝作为选择态和主操作色；橙红色强调到手价与限时优惠；白色与浅灰底承载商品照片。界面中蓝色大面积铺底主要见于订单类型切换、会员权益与品牌素材，日常菜单仍以亮色内容为主。
- **场景差异**：即享商城的促销活动可使用更浓烈的红橙色，礼品卡展示多样卡面，AI Lucky 使用插画与渐变；这些营销视觉没有扩散到日常门店菜单的基础控件。
- **图片与信息配比**：菜单列表先看到杯身，再读商品名、短卖点、价格与加购；商品详情和专题使用更大的图片。图像承担辨认产品的任务，不能只放在装饰区域。
- **密度和尺寸**：主流程的标题、价格、按钮区分明确，但列表项紧凑。横向专题、纵向品类、卡片和底部固定操作区形成稳定的导航结构；不需要给每一栏都做同样大的标题和空白。
- **文案**：原价、券后估价、最终预览金额分别标识。规格以一行摘要回显。不可用券与待生效券展示原因或状态；底部主要操作紧贴当前订单状态。
- **平台适配**：手机使用底部导航和抽屉；Codex 桌面全局应用应保留宿主标题栏，并将信息密度调到与桌面其他界面相近。避免照搬手机的大幅弹窗、漂浮营销入口或重复品牌导航。

## 对现有插件的设计建议

1. 搜索结果继续以真实商品图为主视觉，压缩每项高度；将名称、规格摘要、预估价和操作放在一次扫视范围内。无图时维持稳定的占位尺寸。
2. 商品详情把图片、可选规格、当前 SKU 和预计价格放在首屏；长篇说明仅在用户需要时展开。规格改变后显式更新价格和选择摘要。
3. 购物车与确认界面优先呈现门店、取餐方式、商品规格、数量、预览金额与提交边界；促销信息只在官方结果真实返回时展示。
4. 对话内确认卡片保持紧凑：一个可复核的订单摘要、一个明确的确认动作和一个返回修改入口。宿主标题和聊天输入由 Codex 绘制，不在插件中重复。

## 已用于插件的改进

- 商品搜索使用紧凑的杯图列表，名称、卖点、价格和选规格入口集中展示。接口返回预估价时标注“预估到手”；只有真实返回更高的基础价时才显示划线价。
- 商品详情将图片、名称和价格并列排列。蓝色描边、浅色底及选中标记共同表达规格；暗色主题保留中性底色，使用更清楚的选中边框。无图时使用稳定占位，空详情不再用营销横幅占据主要空间。
- 每次规格更新使用返回的新 SKU 和完整属性列表。实机发现温度切换可能连带改变杯型，因此界面提示其他属性的同步变化，并持续显示完整“已选”摘要。请求期间暂停加购；失败时保留之前的已确认选择。
- 购物车先显示自提门店，再显示缩略图、规格、数量和商品预估小计。修改商品或门店后，应用内的旧确认预览失效。门店切换入口会提前说明清空购物车的影响。
- 确认卡片区分“待确认”“待付款”“取消请求已提交”等状态。待付款金额不会标为已支付；未返回金额时显示待确认或隐藏金额，避免显示为零。支付时限只引用官方渠道，不从 App 截图复制一个固定倒计时。
- 桌面保留三栏和 12–13px 内容字号，标题为 16–18px。窄侧栏使用“选商品 / 选规格 / 购物车”分步切换；触屏保留 44px 控件。宿主标题栏仍只保留一层。

## 验证边界

2026-10-15 的首次浏览覆盖结算页、优惠与支付方式选择，临时调研商品已清除。随后按用户指定的门店、商品和规格，在用户确认冰饮杯型后通过真实 App 提交了一笔订单；微信付款验证页未输入密码，退出支付后，瑞幸订单详情显示“待付款”。此结果验证的是官方 iPhone App 的流程；插件 MCP 的真实下单仍需独立验收。

原始截图包含账号、位置及订单信息，仅在本机忽略目录保存。商品、券、价格和门店状态会随时间与账号变化；本文件记录界面结构，不维护实时报价或后续订单状态。
