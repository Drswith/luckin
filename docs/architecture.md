# 架构与信任边界

## 组件

```text
Codex 本地社区插件
  ├─ skills：引导查询、预览与用户界面确认
  └─ stdio MCP Server
       ├─ upstream.js：固定八个官方工具、Bearer 认证、错误与凭据过滤
       ├─ reviews.js：五分钟一次性凭据、订单预览版本与失效
       ├─ local.js：本插件凭据、最近门店、搜索、本机创建订单
       ├─ orders.js / products.js：状态、金额、取餐、官方图片及链接映射
       └─ MCP Apps
            ├─ app.html：结果轮播、认证、预览、取消、回执、取餐状态
            ├─ shop.html：global / thread 共用选购应用
            └─ shared.js：宿主桥接、主题、密码表单与能力回退
```

`plugins/luckin/` 是源码；`pnpm check` 生成 `release/luckin/`，市场清单指向该安装包。服务器读取 HTML 后嵌入共享脚本，以完整内容哈希注册资源，避免宿主复用旧界面。选店 modal 复用 `shop.html` 的专用视图；不复制选店业务。`mcp.json` 只声明本地启动与插件工作目录，不承载凭据；入口及显示模式由 MCP 工具和资源的 metadata 声明，不杜撰清单字段。

## 查询与本地记录

上游允许列表严格限制为 `queryShopList`、`searchProductForMcp`、`queryProductDetailInfo`、`switchProduct`、`previewOrder`、`createOrder`、`queryOrderDetailInfo`、`cancelOrder`。选店坐标由用户提供；不获取设备定位或地理编码。门店营业时间按中国时区判断，未知时间明确显示状态待确认；不补造缺少的轮播项。

最近门店、搜索各保留八条；成功创建的订单最多五十条，标注“仅本机记录”。普通查单不会加入本插件订单列表。记录保存到用户目录，不使用 iframe localStorage，升级安装包不会删除记录。最近门店从磁盘重新选择时用官方门店查询核对；订单查询结果仅更新已有本机记录。订单记录包含原商品/SKU、门店、订单号及官方返回的付款链接，因此整个目录必须保持私有，也不能提交到仓库。

“再来一单”只把原商品/SKU 带入购物车，再通过 `previewOrder` 获取当下有效性和价格。任何售罄、下架、规格变化或门店变化都以新响应为准，不绕过确认。金额未知显示待确认，不填零。

## 预览与写操作

1. 购物车和门店变更通过仅界面可见的 `invalidate_previews` / `select_shop` 作废服务端旧订单预览。`prepare_cart` 固定待预览参数及版本；面板消息原样传递 `cartRevision`。
2. `review_order` 调用 `previewOrder` 前后检查版本，核对门店 ID、坐标与订单预览金额，保存完整创建参数。这样，正在请求中的旧预览和延迟到达的旧购物车消息都不能获得有效确认。
3. 用户实际点击后才由 `confirm_order` 消耗随机凭据并调用 `createOrder`。五分钟到期、重复使用、换店或购物车变化均拒绝。确认先消耗再请求，即便网络错误也不重复提交；应先查订单状态。
4. `review_cancel` 仅查询状态；用户默认保留订单。`confirm_cancel` 提交取消后自动再调用一次订单详情，只有最新状态 100 才显示已取消。自动刷新失败时保留“请求已提交，最终状态待核实”。
5. 确认卡使用绝对过期时间；内联卡还检查凭据是否已在别的界面失效。服务端是有效性的最终判定方。

当前同一个 MCP 进程的所有界面共用门店和预览版本。换店会保守地使该进程其他会话的订单预览一同失效；这会要求其他会话重新预览，不会把旧预览提交到新门店。确认凭据在内存中，重启即失效。本地记录文件用于单用户本地进程，不承诺多个独立进程同时写入的事务隔离。

## 认证

`save_token`、`confirm_order`、`confirm_cancel` 的可见性严格为 `["app"]`。模型不能调用、也不能模拟点击。Token 来自密码输入框或 `LUCKIN_MCP_TOKEN`，仅经本地 RPC 和官方 Bearer 请求，不进入聊天、工具文本或界面回显。保存为 600 文件，目录为 700；原始网络异常不外传。401 显示认证卡，用户重连后恢复只读请求；创建与取消不会自动恢复执行。

CLI 的凭据路径、格式与第三方读取许可未确认，故没有自动 CLI 登录或凭据读取。详情与来源见[认证调研](authentication-research.md)。`visibility` 由宿主执行，本地 stdio 不能提供强真人证明，也不能防止不可信宿主记录输入。

## 界面与宿主

未连接时，侧面板和全屏顶部仅保留紧凑状态条；点击“连接账号”后就地展开最多 400px 的手动 Token 卡片，收起会移除密码框及其内容。只对选店和搜索区域置灰并禁止交互，详情、购物车和本机订单不整体压暗。连接成功后收起卡片并解除查询区禁用；窗口重新获得焦点不会重建正在填写的表单。

- `open_luckin` 保留 `global` / `thread` 入口并接受可选门店、商品和展开门店参数。两处都使用相同 HTML；≥ 960px 三栏，较窄为三步标签。
- 门店条在面板内就地展开。只有内联“换店”尝试 `requestModal`，不支持时发消息请求打开选购面板并展开门店条；无消息能力时使用插件 deep link。宿主最终是否落在会话侧面板须实测。
- 内联结果最多五家门店、八个商品；每张卡单一目的、最多两个操作。卡片宽度最多 400px，按钮随内容、靠右，主按钮最右；不绘制宿主标题栏或输入框。
- 预览先通过 `ui/message` 生成对话确认卡；无能力或调用失败时回退面板确认。同样的服务端凭据适用于两个位置。
- 取餐状态 20/30/60 可进入 PiP，45 秒轮询订单详情。仅 `takeMealCodeInfo.code` 和有效 `aboutTime` 都存在时显示完整版，否则只显示状态、更新时间和刷新。10 留在待付款回执；80/100 停止轮询并退回 inline。宿主拒绝 PiP 时继续内联显示，不伪造支持。
- 主题来自 `hostContext.theme` 和 `host-context-changed`，兼容 `window.openai.theme`，缺省跟随系统。主蓝 `#0022AB`，选中浅底 `#F2F4FF`，深色选中描边 `#4A63F0`、文字 `#8FA0FF`；价格浅色 `#F95234`、深色 `#FF5A36`，数字优先 DIN 字体。
- 商品原价、商品预估价、订单预览金额、待支付金额各自标识，不把创建订单当成已支付。不返回付款时限就不显示倒计时；付款链接只来自官方响应，并限制 HTTPS 官方域。

资源 OpenAI metadata 使用当前合法的 inline/fullscreen，MCP Apps 初始化能力声明另包含 pip；没有向只接受两种模式的 OpenAI metadata 填入非法枚举。能力声明不等于宿主支持。当前公开扩展规范与旧运行时对 PiP 的描述存在差异，见[认证与宿主调研](authentication-research.md)。真实 Token、跨界面确认、PiP/modal、浏览器打开方式均是单独验收项，详见[开发验证](development.md)。
